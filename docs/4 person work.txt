## Collaboration rules

- Only Person 1 edits `schema.prisma` and migration history.
- Every API change must include a validation schema and authorization test.
- Every member writes tests for their own feature; Person 4 does not become the sole test writer.
- Shared DTOs should be agreed before UI work starts.
- Do not merge UI-only success behavior before the backend endpoint exists.
- Use one feature branch per subsystem, not one branch per person for the entire project.
- Merge in dependency order: Person 1 foundation → Person 2/3 core APIs → Person 4 integrations → final UI and E2E.
- No member should silently add a static or browser-storage fallback when an API fails.
